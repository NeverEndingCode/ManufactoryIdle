# Phase 3a: the API, the schema, and guest play — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new `apps/api` (Fastify) serves a guest a real server-side world over HTTP: `POST /api/guests`, `GET /api/world`, `POST /api/actions` (the D.2 lifecycle with a row lock), and `GET /api/health`. It persists to Postgres through a small `Db` interface, and is tested in-process on PGlite. The engine gains a public `schedule()` for D.2's `eventSchedule`.

**Architecture:**
- **Task 1:** `schedule` in the engine.
- **Task 2:** the `apps/api` scaffold, the `Db` interface with PGlite and `pg` adapters, the migration runner and migration 001.
- **Task 3:** content loading, `content_versions`, and the LRU.
- **Task 4:** players, worlds and the three routes.
- **Task 5:** the process entry (`main.ts`), docs and the README.

**Tech Stack:** TypeScript ESM, Fastify 5, `pg` 8, `@electric-sql/pglite` 0.5, vitest, tsx, pnpm + turbo.

**Spec:** `docs/superpowers/specs/2026-10-16-phase-3-server-design.md` (PR 3a section, and rulings R-1 through R-11).

## Review Focus

- **Atomicity.** A batch that fails on its *k*th action persists nothing: no state, no `state_version` bump, no `action_log` row. Covered by Task 4 test 4.
- **Read without write.** `GET /api/world` must not change `state_version`, `last_resolved_at` or `state`. Covered by Task 4 test 2.
- **Replayability.** The `action_log` alone, replayed through `resolve` and `applyBatch` from the world's initial state at its recorded times, reproduces the stored state. Covered by Task 4 test 8.
- **Version pinning.** A world created on content A is still served with A after the server starts on content B. Covered by Task 3's and Task 4's version tests.
- **Prototype keys.** Request bodies are parsed by Fastify's JSON parser. `__proto__` in a body must not reach engine records; Fastify's default `onProtoPoisoning: 'error'` rejects it, so keep the default.

export interface Schedule {
  /** World time (ms) the schedule describes: state.lastResolvedAt. */
  atMs: number;
  /** Per stock item: liquid stock now (canonical decimal string) and net rate per second. */

}

```

// db.ts
export interface Db {
  query<T = Record<string, unknown>>(sql: string, params?: unknown[]): Promise<T[]>;
  /** Runs fn in one transaction; commits on resolve, rolls back on throw. Nested calls reuse the outer transaction. */
  transaction<T>(fn: (tx: Db) => Promise<T>): Promise<T>;
  close(): Promise<void>;
}
// pglite.ts
export async function pgliteDb(): Promise<Db>;              // in-memory PGlite
// pg.ts
export function pgDb(connectionString: string): Db;          // pg.Pool; transaction() takes one client: BEGIN/COMMIT/ROLLBACK
// migrate.ts
export async function migrate(db: Db, dir?: string): Promise<string[]>;  // applies pending NNN-*.sql in order, returns applied names
```

- **`package.json`:** name `@manufactory/api`, `private`, `"type": "module"`, `main` `./src/main.ts`.

  - **Dependencies:** `@manufactory/engine` and `@manufactory/content` (`workspace:*`), `fastify`, `pg`, `@electric-sql/pglite`.

- **`tsconfig.json`:** extends the base config, `types: ["node"]`, includes `src/**/*.ts`.
- **`001-initial.sql`:** D.3's schema, adjusted as follows.
  - **`content_versions`:** `(version text pk, checksum text not null, bundle jsonb not null, published_at timestamptz not null default now())`.
  - **`players`:** `id uuid pk default gen_random_uuid()`, `supertokens_user_id text unique`, `guest_token text unique`, `display_name text`, `timezone text not null default 'UTC'`, `created_at timestamptz not null default now()`, `last_seen_at timestamptz not null default now()`, and `current_rank int not null default 0`, `lifetime_tickets numeric not null default 0`, `leaderboard_score numeric not null default 0`, with a check that exactly one of `supertokens_user_id` and `guest_token` is non-null.
  - **`player_worlds`:** `id uuid pk default gen_random_uuid()`, `player_id uuid not null references players on delete cascade`, `world_type text not null default 'main'`, `expedition_id text`, `content_version text not null references content_versions`, `state jsonb not null`, `state_version bigint not null default 0`, `last_resolved_at timestamptz not null`, `schema_version int not null`, and `unique(player_id, world_type, expedition_id)`. Postgres treats nulls as distinct, so use `unique nulls not distinct`, which needs PG 15+ and PGlite.
  - **`action_log`:** `id bigserial pk`, `player_id uuid not null`, `world_id uuid not null references player_worlds on delete cascade`, `actions jsonb not null`, `idempotency_key text`, `created_at timestamptz not null default now()`, plus an index on `(world_id, created_at)`.

  - **`sessions`:** `id bigserial pk`, `player_id uuid not null references players on delete cascade`, `opened_at timestamptz not null default now()`, `closed_at timestamptz`, `client text`.
  - If PGlite doesn't support `gen_random_uuid()` or `nulls not distinct`, find the equivalent that works on both PGlite and Postgres 16 (for example the `pgcrypto` extension, or generating uuids in TypeScript with `crypto.randomUUID()`). Say which you used.
- **The migration runner:** creates `schema_migrations(version text pk, applied_at timestamptz not null default now())` if it's absent, then applies each not-yet-applied file in name order, each in its own transaction, and records it.

### Task 4: players, worlds and the routes, test-first

**Files:**
- Create: `apps/api/src/worlds.ts`, `apps/api/src/server.ts`, `apps/api/src/http/actions-schema.ts`
- Test: `apps/api/src/server.test.ts`

**Interfaces:**

```ts
export type Auth = (request: FastifyRequest) => Promise<{ playerId: string } | null>;
/** The 3a resolver: `Authorization: Guest <token>` → that guest player's id, else null. */
export function guestAuth(db: Db): Auth;
export interface ServerDeps { db: Db; content: ContentStore; clock: () => number; auth: Auth; }
export function buildServer(deps: ServerDeps): FastifyInstance;
```

**Routes:**
- **`GET /api/health`:** returns `{ ok: true, contentVersion: content.current.version }`.
- **`POST /api/guests`:** no auth. Generates a token with `crypto.randomBytes(32).toString("base64url")`. In one transaction it inserts a player (guest token) and a world: `initialWorld(content.current.content, seed, clock())`, where `seed` is a fresh 32-bit integer from `crypto.randomInt`. The world is stored with `content_version = current.version`, `state_version = 0`, `last_resolved_at = clock()` and `schema_version = state.schemaVersion`. Returns `201 { guestToken, world: worldView }`.
- **`GET /api/world`:** auth required (`401` without). Loads the main world and resolves it to `clock()` with `resolve(state, content, clock() − state.lastResolvedAt)` **in memory only**. Returns `200 worldView`.
- **`POST /api/actions`:** auth required. The body schema is `{ idempotencyKey: string (1..128), baseVersion: integer >= 0, actions: Action[] (1..100) }`.
  - Validate each action with a Fastify JSON schema in `actions-schema.ts`: a `oneOf` over the D.1 types, where every field is typed, `additionalProperties: false` is set, and `recipeId` on `BUY_MACHINE` is optional.
  - Do the D.2 transaction:
    1. `SELECT … FOR UPDATE` the main world.
    2. Load its pinned content with `content.get(row.content_version)`.
    3. `resolve` to `clock()`.
    4. Run `applyBatch(resolved.state, content, actions, resolved.state.seed)`.
    5. On rejection, throw a typed error carrying the failing index, action and reason, so the transaction rolls back, and map it to `409 { failedAction, index, reason }`.
    6. On success: `UPDATE … SET state, state_version = state_version + 1, last_resolved_at = to_timestamp(clock()/1000)`, `INSERT INTO action_log`, update `players.last_seen_at`.
    7. Return `200 { ...worldView, summary }`.
  - Read `applyBatch`'s result type for how it reports which action failed.
- **`worldView`:** `{ state: JSON.parse(serializeWorld(state)), schedule: schedule(state, content), stateVersion, contentVersion }`.

- [ ] **Step 1: Write the failing tests** (`server.test.ts`). Use PGlite, `migrate`, `openContentStore(db, SLICE_DIR)`, a mutable fake clock and `guestAuth(db)`, with requests through `app.inject()`. Each test builds a fresh db.
  1. **`POST /api/guests`** returns `201` with a token. The world's `state` deep-equals `serializeWorld(initialWorld(content, seed, now))`, where you read the seed from the stored state. One player row and one world row exist.
  2. **`GET /api/world`:** after advancing the clock 10 minutes, it returns stock equal to `resolve(initial, content, 600_000).state`'s, serialized. The db row's `state_version`, `last_resolved_at` and `state` are unchanged.
  3. **An affordable action.** `POST /api/actions` with one affordable action (find one for the slice's starting world, for example a `BUY_MACHINE` of the first live miner; check `affordableCandidates` in `apps/sim/src/policies.ts` for how to find one) returns `200`. The state shows the purchase, `state_version` is 1, one `action_log` row holds the actions and the idempotency key, and `last_resolved_at` equals the clock.
  4. **Atomicity.** A batch `[affordable, unaffordable]` (the second, for example, buying 1,000 of something) returns `409` with `index: 1` and a non-empty `reason`. `state_version` is still 0, and there are no `action_log` rows.
  5. **Malformed bodies:** an unknown action type, a missing field, an extra field, and `actions: []` each return `400`, and nothing changes.
  6. **Auth:** no `Authorization` header gives `401` on `/api/world` and `/api/actions`; an unknown guest token gives `401`.
  7. **Version pinning.** Create a guest on a store opened with the fixture bundle, then build a second server on the same db with a store opened on the slice. `GET /api/world` serves the world with the fixture content (its items are the fixture's), and `contentVersion` is the fixture's checksum.
  8. **Replay.** After three successful `POST /api/actions` calls at different clock times, replaying from the initial state reproduces the stored state exactly (compare serialized). The row's `created_at` must hold the fake clock time, so insert `created_at` explicitly from `clock()`, not `default now()`.
